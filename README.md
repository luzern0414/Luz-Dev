# Luz Dev

把已批准的产品设计做成可上线、合规的生产系统。

![Agent Skill](https://img.shields.io/badge/Agent%20Skill-luz--dev-green)

</div>

Luz Dev 是一个 Agent Skill。它接手 Luz System 批准的系统设计，完成后端服务、接口、数据库、业务逻辑、前端对接、部署运维、资质与协议，直到上线验收。每个任务先写技术方案，你批准后才动代码、数据或线上环境。

## 能做什么

- **先方案、后动手**：实现、排查、分析、运维都先出一份技术方案，写清调研依据、系统功能、改动范围、风险和验收。批准与方案内容哈希绑定，内容变了要重新批准。
- **常见业务逻辑**：订单与库存防超卖、价格与优惠券、储值与积分、预约、售后、支付与退款、定时任务、缓存、多门店隔离，附带有测试的参考实现。
- **前端对接**：读取 Luz System 交付的设计与原型，接入小程序、管理后台或应用。页面和操作编号与设计一致，原型里的模拟数据全部换成真实接口数据。
- **安全与规范基线**：接口与登录安全、HTTPS、容器部署、持续集成与回滚、监控告警、备份恢复、密钥与依赖安全、数据保护与等级保护，每条规则都有调研来源。
- **上线准备**：运维手册、经营资质与备案、软件许可、用户协议与隐私政策、上线验收清单。
- **知识与经验**：调研读过的来源和得出的结论存进知识库；每次调用学到的偏好、教训和有效做法存进经验库，下次先查再做。

## 适合 / 不适合

适合：

- 设计已经批准，要把系统做出来、接上前端、部署上线。
- 给现有系统加业务功能、排查故障、做上线前检查或运维变更。
- 想知道同类系统怎么做，需要有来源的技术方案。

不适合，请改用：

| 需求 | 改用 |
|---|---|
| 确定模块范围、系统架构、功能清单、界面与原型、硬件选型 | Luz-System |
| 配色、字体、海报、文档排版（Word、Excel、PPT、PDF、阅读页） | Luz-Design |
| 文章、文案、协议正文的写作与润色 | Luz-Writing |
| 单纯抓取网页或搜索资料 | Luz-Crawl |

## 快速开始

1. 把本目录放进 Agent 的技能目录（例如 `~/.claude/skills/luz-dev`）。
2. 安装 Python 3.11 及以上和 `requirements.txt` 中的依赖。
3. 把配套技能放在同级目录：前端设计来自 Luz-System 的会话目录（`skill输出/Luz-System/NNN-项目/`）；页面的主题色和 `check_document.py` 检查脚本来自 Luz-Design；调研用 Luz-Crawl；协议与上线文案用 Luz-Writing。
4. 直接提需求，例如：
   - “按批准的设计，把健身房小程序和后台的后端做出来。”
   - “给订单模块加上库存防超卖和超时关单。”
   - “检查这个系统上线前还缺哪些安全配置和资质。”
   - “写一份部署到云服务器的方案，包含备份和回滚。”

安装后可以运行自检，确认配套技能已找到：

```powershell
python -m pip install -r requirements.txt
python -X utf8 scripts/validate_skill_package.py --design-root ../Luz-Design
```

## 工作方式

1. **查经验**：先检索经验库和知识库，应用已记录的偏好和教训。
2. **调研**：用 Luz-Crawl 读同类系统、各模块的做法、外部平台官方文档和相关法规，结果写回知识库。
3. **写方案**：一个需求一个项目文件夹（`skill输出/Luz-Dev/NN-主题/`），里面是一个成品 HTML 和 `raw/` 过程文件。方案先列基础功能和定制功能，再写模块详细设计、安全、上线与合规。页面必须通过 Luz-Design 的检查脚本。
4. **你批准**：只认你的明确批准。批准记录方案内容哈希，开发前和每批改动前都要通过门禁检查。
5. **实现与对接**：先做最小可用的完整链路，接口契约先行；前端按 Luz System 的设计接入，覆盖检查必须通过。
6. **上线**：按发布流程部署，逐项完成上线清单并留下证据，上线后观察。
7. **沉淀**：把这次学到的偏好、教训和有效做法写进经验库。

范围变化时修订同一份方案并重新批准，代码不偏离批准的方案。

## 经验沉淀

每次调用结束前，都会记录你提出或纠正的偏好、证明有效或失败的做法和参数、对规则的修正，只记通用原则，不记任务细节。条目按主题 key 存放：同一主题再次记录会替换旧内容，只保留一次旧版本用于追溯，不会越积越多。偏好最多 60 条、教训和有效信息各 120 条、有效经验记录 120 条，超出时先清理长期未确认、使用最少的条目；检查脚本会拦下重复主题、重复内容和个人信息。

## 目录结构

```text
SKILL.md       技能入口：顺序、路由、工程规则、每次调用后沉淀
WORKFLOW.md    各阶段的进入条件、产出和门禁
references/    业务模式、模块详细设计、规范基线、调研、前端对接、运维、合规与协议
backend/       业务模式的参考实现与测试
contracts/     与 Luz System 的交接契约（字段定义与校验）
knowledge/     调研知识库：来源、事实、搜索记录
experience/    经验库：偏好、教训、有效信息、任务经验与可复用实现
assets/        方案模板、部署模板、协议模板、页面样式
scripts/       方案、调研、知识库、经验、交接校验、技能注册等脚本
agent/         智能体运行时与协议
tests/         测试
```

## 五个技能的分工

| 技能 | 分工 |
|---|---|
| [Luz-System](https://github.com/luzern0414/Luz-System) | 系统设计：模块范围、架构、功能清单、界面与可交互原型、硬件选型，经批准后交给 Luz Dev |
| [Luz-Design](https://github.com/luzern0414/Luz-Design) | 视觉标准、海报与品牌视觉、文档与阅读页排版及检查脚本 |
| [Luz-Dev](https://github.com/luzern0414/Luz-Dev) | 本仓库：后端、业务逻辑、前端对接、部署运维、资质与协议、上线验收 |
| [Luz-Writing](https://github.com/luzern0414/Luz-Writing) | 写作与改稿：文章、文案、用户协议与隐私政策正文 |
| [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) | 用真实浏览器搜索和抓取网页，供各技能调研 |
