# 业务闭环结果页与恢复路径

## 摘要

以服务端持久状态作为唯一事实源，为支付、表单、异步任务、部分成功和失败恢复定义可深链、可刷新、可测试的闭环结果落点。

## 决策与做法

- 低风险可逆操作留在当前页就地更新并显示短 Toast；可修正校验失败返回原表单并保留全部输入。
- 支付、申请、新建实体和多步骤表单完成后使用独立结果页并 replace 历史；结果页仅依据服务端 state、terminal 和 next_action 渲染。
- 支付 SDK 返回后先显示正在确认，按 1、2、4、6、8 秒有界轮询；超时仍 unknown 时显示结果确认中并提示请勿重复支付。
- 异步任务使用处理中页并可稍后查看；批次部分成功使用成功、失败、跳过汇总页，并仅重试失败项。
- 结果编号只证明已提交或已创建，不隐含审批通过、履约完成或退款到账；终态失败页说明副作用、可重试性与支持编号。

## 失败尝试与教训

- 生成功能目录页时 JavaScript 参数名 function 触发保留字语法错误；改为 fn，并加入生成脚本与测试防回归。
- 旧 Design 目录路径指向残缺副本；将默认解析修复为与 Luz-Dev 同级的真实 Luz-Design 包。
