# 商业资质、备案与许可

上线需要的主体资质、备案、平台资质与第三方许可。项目方案在“上线与合规”章节逐项列出：是否适用、负责人（通常是商户）、办理进度、证据位置。法规与平台规则以官方原文为准；本篇标注“待调研核对”的条目，必须在项目调研中读到官方原文后再写进方案。

## 1. 资质与备案清单

| 事项 | 何时需要 | 要点 | 状态 |
|---|---|---|---|
| 主体资质 | 所有上线项目 | 营业执照（或其他主体证明）；小程序、商户号、备案的主体信息一致 | 通用 |
| 小程序主体认证 | 小程序 | 小程序账号完成主体认证后才能使用支付等能力 | 待调研核对 |
| 小程序服务类目与资质 | 小程序 | 按实际业务选择类目并上传对应资质（如健身、餐饮、医疗等各有要求）；类目与功能不符会审核失败 | 待调研核对 |
| ICP 备案（网站与小程序） | 后端服务器域名、管理后台域名、小程序本身 | 小程序服务器域名需要已备案的 HTTPS 域名；小程序本身的备案要求以工信部与微信官方说明为准 | 待调研核对 |
| 增值电信业务经营许可证 | 经营性互联网信息服务、平台型业务 | 是否需要取决于业务形态（自营还是平台、是否收取信息服务费）；在方案中写明判断依据 | 待调研核对 |
| 网络安全等级保护 | 信息系统运营者 | 定级、备案与测评要求随级别不同；方案写明定级判断 | 待调研核对 |
| 微信支付商户号 | 线上收款 | 商户号与小程序 appid 必须有绑定关系，否则下单报 APPID_MCHID_NOT_MATCH；申请 JSAPI 支付权限（PAY-002） | 已核对（微信支付官方文档） |
| 交易类小程序发货管理 | 小程序内收款 | 按《交易类小程序运营规范》接入订单发货管理，否则可能被限制支付（MP-005） | 已核对（微信支付开发指引） |
| 人脸识别 | 采集或使用人脸 | 单独同意、非唯一方式、影响评估（报告保存 3 年）、存储达 10 万人 30 个工作日内备案；不得在更衣室等私密空间安装（FACE-001～006） | 已核对（人脸识别技术应用安全管理办法） |
| 预付卡 / 储值 | 售卖储值卡、会员卡、次卡 | 冷静期、退费、原路退回按当地规定与合同示范文本；发卡备案等要求按地区核对（MBR-002） | 部分核对（北京示范文本） |
| 抽奖 / 有奖销售 | 抽奖、有奖活动 | 规则事先公示、最高奖不超过 5 万元、不得内定（MKT-004） | 已核对（规范促销行为暂行规定） |
| 个人信息保护 | 所有收集个人信息的项目 | 处理规则公开、最小必要、敏感信息单独同意、影响评估、删除（PII-*） | 已核对（个人信息保护法） |

## 2. 软件与素材许可

| 对象 | 风险 | 做法 |
|---|---|---|
| 开源依赖 | GPL / AGPL 要求衍生作品开源（AGPL 覆盖网络服务）；部分“开源”商城源码商用需要购买授权 | 依赖清单记录许可证；默认只用 MIT、BSD、Apache-2.0 等宽松许可；引入 GPL / AGPL 或带商业授权的源码需用户确认 |
| 参考开源项目 | 直接复制代码会继承其许可证 | 调研参考的开源系统只借鉴设计；复制代码时保留许可证声明并核对许可 |
| 字体 | 部分系统字体不允许商用嵌入 | 使用可商用字体（如以 SIL OFL 授权发布的字体），记录来源 |
| 图片、图标、插画 | 版权与肖像权 | 使用自有、已购买或明确可商用的素材；Luz Design 或 Luz System 生成、选用的素材附权利证据 |
| 地图、短信、人脸等第三方服务 | 服务协议与计费 | 记录服务商、协议、计费方式与到期时间 |

依赖许可证清单放在 `config/third-party-licenses.md`，发布前检查（LIC-001）。

## 3. 在方案中如何写

“上线与合规”章节包含一张表：事项、是否适用（含判断理由）、负责方、进度、证据（证照编号末几位、截图路径、官方回执），以及预计耗时对排期的影响（备案、类目审核、商户号申请都需要时间，应在开发初期启动）。
