# 售后：仅退款、退货退款

参考代码：`backend/10-after-sales/code/after_sales/__init__.py`，测试 5 项（含随机申请 / 驳回 60 轮不超退）。
相关：pricing.md（分摊与退款金额）、`backend/09-wechat-pay/MODULE.md` §7（渠道退款）、inventory.md（退货回库）、accounts.md（积分回扣）。
相关规范：RFD-001～RFD-005、AUTHZ-001、OBS-002。

## 1. 类型与状态

| 类型 | 流程 |
|---|---|
| 仅退款 | 申请 → 审核通过 → 退款中 → 已退款 |
| 退货退款 | 申请 → 审核通过 → 待退货 → 已收货 → 退款中 → 已退款 |
| 换货（按需） | 申请 → 审核 → 待退货 → 已收货 → 重新发货（不涉及退款） |

状态：`applied → approved | rejected | cancelled`；`approved → return_pending | refunding | cancelled`；`return_pending → returned | cancelled`；`returned → refunding`；`refunding → refunded | refund_failed`；`refund_failed → refunding`。`rejected`、`cancelled`、`refunded` 为终态。

## 2. 额度控制（防超退）

- 订单支付成功时为每一行写入可退额度：数量、行实付（已分摊优惠）。
- 申请时原子占用数量和金额：`reserved_qty + n <= qty`，条件更新带上旧值，并发申请只有一个成功。
- 本次金额 = 行实付 × 占用后数量 // 总数量 − 已占用金额；驳回 / 撤销时按实际金额释放。任何顺序下全部退完合计等于行实付。
- 退款单号固定为售后单号，失败重试沿用（RFD-002）。

## 3. 规则

| 规则 | 做法 |
|---|---|
| 售后期 | 支付后 N 天内可申请（商户配置）；服务类（课程、年卡）按使用情况与合同规则计算 |
| 本人订单 | 只能对本人订单申请；后台审核需要退款权限并写审计 |
| 驳回 | 必须填写原因并通知用户 |
| 退款执行 | 进入退款中时写发件箱，支付模块调用渠道退款；退款结果回调幂等 |
| 回滚 | 退款成功后按方案：库存 / 名额回补、券退回、积分回扣、权益收回（RFD-004） |
| 虚拟 / 服务商品 | 已核销、已开课部分不可退或按比例退；规则写入商品与合同 |

## 4. 测试清单

- 超出可退数量被拒；驳回后额度释放可再申请。
- 随机申请、驳回顺序下累计金额不超过实付，全部退完等于实付。
- 仅退款与退货退款流转；退款失败可重试且退款单号不变。
- 售后期外、非本人订单被拒；已撤销的售后不可审核。
