# 计价、优惠叠加与分摊

参考代码：`backend/17-campaign/code/pricing/__init__.py`（`quote`、`allocate`、`refund_amount`），测试 9 项（含随机性质测试）。
相关：order.md（试算与提交）、after-sales.md（按分摊退款）、`backend/16-coupon/MODULE.md`。
相关规范：MONEY-001～MONEY-003、MKT-001、MKT-002、MKT-004。

## 1. 计价管线

```text
商品小计（价格快照 × 数量）
 → 单品 / 会员价（替换单价，不叠加为“优惠”）
 → 活动优惠：满减、折扣（按优先级；同一互斥组取最优）
 → 优惠券（门槛按活动后金额判断；默认一单一券）
 → 积分抵扣、余额支付（属于支付方式，不改变订单应付）
 → 运费
 = 应付（不小于 0）
```

顺序是商户口径，方案里必须写明并让商户确认（列入待决问题）。前端只展示服务端返回的试算结果（MONEY-002）。

## 2. 叠加与互斥

| 规则 | 做法 |
|---|---|
| 互斥组 | 同一 `exclusive_group` 内只取优惠最大的一个，其余记入“未使用原因” |
| 优先级 | `priority` 小的先算；后算的优惠以前面优惠后的金额为基础 |
| 适用范围 | 按商品、分类限定；不适用的行不参与该优惠的门槛与分摊 |
| 券 | 默认一单一券；可叠加的券需显式分组 |
| 下限 | 每行优惠不超过该行金额，整单应付不小于 0 |
| 未使用原因 | 返回“未达门槛 / 无适用商品 / 互斥组内优惠较小”，前端用于提示 |

## 3. 分摊（必须做）

整单优惠要按适用行的金额比例分摊到每一行，写入订单明细：

- 部分退款按“行实付”计算，不能按原价，也不能重新计算优惠（MONEY-003）。
- 对账、报表的商品销售额以行实付为准。

算法：最大余数法。先按比例向下取整，剩余的分按小数部分从大到小逐一补齐，合计严格等于优惠额（`allocate`）。

## 4. 部分退款金额

同一行分多次退款时，用累计公式保证退完时合计等于实付：

```text
本次应退 = 实付 × (已退数量 + 本次数量) // 总数量 − 实付 × 已退数量 // 总数量
```

售后模块在此基础上记录已占用金额，任意申请与驳回顺序下都不会超退（after-sales.md）。

## 5. 折扣取整

折扣向下取整到分（商户少让利，不多让利）；规则写入方案，并与前端展示一致。

## 6. 测试清单

- 分摊合计严格等于优惠额；每行分摊不超过行金额（随机 500 组）。
- 满减门槛、适用范围、互斥组取最优、券门槛按活动后金额判断。
- 应付不为负，任何一行实付不为负。
- 分多次部分退款，合计等于行实付（随机 300 组）。
