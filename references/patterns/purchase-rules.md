# 购买规则：起售、限购与购买资格

相关：order.md、catalog-cart.md、pricing.md、coupon.md、seckill.md。相关规范：ORDER-011、ORDER-012、MKT-006、ADMIN-005。参考代码：`backend/08-order/code/order/purchase.py`，测试 `test_order_purchase_rules.py`、`test_order_concurrency.py`。

## 1. 先分清三件事

| 事 | 管什么 | 在哪 | 例子 |
|---|---|---|---|
| 库存 | 全店还剩多少 | 07-inventory（预占、确认、释放） | 剩 5 件 |
| 购买规则 | 每个人、每一单能买多少，谁能买 | 本篇；规则跟着商品或活动走，订单模块校验与计数 | 2 件起售、每人限购 1 次、每日限购 2 件、新客专享 |
| 券与活动的领取、使用次数 | 每人能领几张券、一单能叠几张 | 16-coupon、17-campaign | 每人限领 1 张、每单限用 1 张 |

三者分开计数，互不代替：售罄看库存，“已达购买上限”看购买规则，“已领过”看券。

## 2. 规则清单

规则由运营在后台的商品或活动编辑页里维护（经营规则，保存即生效，写审计），不写死在代码里，也不放运行配置文件（`config-logging.md` §1）。

| 规则 | 字段 | 说明 |
|---|---|---|
| 起售 | `min_qty` | 本单该规则下至少几件，例如“2 件起售” |
| 单笔上限 | `max_per_order` | 本单该规则下最多几件 |
| 每人限购件数 | `limit_qty` | 统计周期内最多几件 |
| 每人限购次数 | `limit_orders` | 统计周期内最多下几单；“只能购买一次”= 1，与件数可同时设（一次最多 2 件：`limit_orders=1`、`max_per_order=2`） |
| 统计周期 | `window` | `all` 不分周期（活动期内用活动自己的规则键区分）、`day`、`week`（自然周，周一开始）、`month`；按门店时区计算 |
| 统计范围 | `scope` | `chain` 全部门店合计；`store` 每家门店分别计 |
| 共享限额 | `key` | 默认每个商品单独计；同一活动的几个商品共用一个限额时填同一个键，例如 `campaign:12` |
| 身份维度 | `identity` | `member` 按会员；`member_phone` 同时按绑定手机号计，一人多个账号也只能买到上限；未绑定手机号的不能买 |
| 退款后退回名额 | `release_on_refund` | 默认是：按退款件数退回件数，行全部退完时退回次数；新人福利、一次性体验类可设为否，防止买了退、退了再买 |
| 新客专享 | `new_customer_only` + `new_customer_basis` | `never_paid` 从未支付过订单；`no_kept_order` 没有保留中的订单（全额退款的不算） |
| 需绑定手机号 | `requires_phone` | 未绑定时提示去绑定 |
| 超出部分按原价 | `over_limit` | `block`（默认）超出不能买；`regular_price` 限购内按活动价并计入名额，超出的件数按商品的原价（`regular_price_cents`，须高于活动价）照常买、不计名额；次数用完、不符合新客或未绑定手机号（按手机号计时）时整行按原价。只能和件数、次数或新客限制一起用 |

以下不在购买规则里，按各自模块做：会员等级或人群专享（会员模块给出资格，行种类解析时判断）、活动时间与每日时段（活动模块判断是否在售）、满减与折扣（17-campaign）。

## 3. 计数模型

| 表 | 字段 | 约束 |
|---|---|---|
| `order_purchase_quotas` | `subject`（`user:<会员>` 或 `phone:<手机号哈希>`）、`counter_key`（`<规则键>\|<all 或 store:<门店>>\|<周期键>`）、`qty`、`orders`、`window_end_at`、`updated_at` | 唯一 (`subject`, `counter_key`)；周期键如 `d20261030`、`w202644`、`m202610`、`all` |

- 名额在**下单时**计入（含待支付），与订单同一事务：条件自增 `qty + n ≤ 件数上限 AND orders + 1 ≤ 次数上限`；首行靠唯一约束裁决并发。任何一项不满足返回 4225，整单回滚，不会出现订单成了名额没扣或反过来。
- 同一单里共用一个计数键的多行先合并再计；多个计数键按键排序依次更新，避免并发死锁。
- `member_phone` 时会员与手机号两行都要满足、都要加。
- 订单行快照记下计入的计数键、主体、件数与单数（单数只记在该键的第一行）。退回时回到原来的周期：昨天下的单今天取消，退回的是昨天的名额。
- 新客专享额外给主体的 `newcomer` 计数行加 1 单（上限 1）：同一个人并发提交两单新客商品也只成一单；首单待支付期间也不能再下新客单。
- 周期结束 7 天后的计数行由定时任务 `order.purge_purchase_quotas` 删除；不分周期的保留。

## 4. 流程

| 环节 | 做法 |
|---|---|
| 商品页、购物车 | `POST /api/v1/app/orders/purchase-status` 返回每条规则的已购与剩余；步进器上限取 min(库存, 单笔上限, 剩余件数)；加购不占名额，登录合并购物车时数量不超过剩余 |
| 试算 | 先把“超出部分按原价”的行拆成活动价行与原价行（`price_tier` = promo / regular），再计价；返回 `purchase_rules`（规则、已购、剩余、按原价的件数 `regular_qty`）与 `issues`；有问题 `submittable=false` |
| 提交 | 同事务再拆行、校验并计入名额（只计活动价部分）；不满足返回 4225，`data.reason` 是稳定代码，`data.issues` 列全部问题；拆行结果与报价不同（活动价名额刚被用掉）时按价格变化请顾客重新确认 |
| 取消、超时关单 | 原数退回件数与次数 |
| 退款成功 | 规则允许时按退款件数退回；该键的行全部退完时退回次数 |
| 改规则 | 只影响之后的订单；调低上限不追溯已下的单；调换规则键等于重新计数，后台改键前提示 |
| 客服例外 | 后台按会员查看计数，必要时调整（需权限、写原因与审计），不直接改库 |

## 5. 问题代码与提示

`issues[].reason` 与 4225 的 `data.reason` 共用一套代码，前端按代码取文案键（模块详设 content），不显示接口原文。

| 代码 | 含义 | 前台提示与出路 |
|---|---|---|
| `below_min_qty` | 不够起售量 | “2 件起售” · 数量自动补到起售量 |
| `over_order_limit` | 超过单笔上限 | “每单最多 3 件” · 数量减到上限 |
| `purchase_limit` | 超过周期件数 | “每日限购 2 件，今日还可买 1 件” · 改数量；剩 0 时按钮改为“已达购买上限”。规则设超出部分按原价时不报这个问题，改为在商品与结算里写“限购 2 件，超出部分按原价 ¥28.00” |
| `purchase_times_limit` | 超过周期次数 | “每人限购 1 次，你已购买” · 去订单查看 |
| `new_customer_only` | 不是新客 | “新人专享，你已下过单” · 看看同款常规商品 |
| `phone_required` | 未绑定手机号 | “绑定手机号后可购买” · 去绑定 |
| `invalid_purchase_rule` | 规则数据不合法 | 不对顾客显示原因，记错误日志；后台保存时就应拦下 |

## 6. 失败与边界

| 情况 | 处理 |
|---|---|
| 并发提交、多端同时下单 | 条件自增裁决，只成上限内的单 |
| 一人多号 | `member_phone` 按手机号再计一份；更严的场景再加微信开放平台统一标识（项目里加主体前缀即可） |
| 跨天支付 | 名额按下单时的周期计，支付时间不影响 |
| 部分退款 | 只退回已退件数；次数等整行退完 |
| 换货、补发 | 不经过下单，不计名额 |
| 后台代客下单 | 同样校验与计数，员工不能绕过；确需例外走客服调整并审计 |
| 超出部分按原价时退款 | 活动价行退款按规则退回名额；原价行不计名额，退款不涉及名额 |
| 活动价与原价同在一单 | 两行分别计价、分摊优惠与退款；结算与订单详情里分两行显示“活动价 ×2”“原价 ×1” |
| 规则数据写错 | 解析时报错、不静默放行；后台保存时按同样的校验拦截 |
| 同一单里两行共用一个键但规则不同 | 视为数据错误，拒绝下单（后台保存时就要保证同键同规则） |

## 7. 测试清单

- 起售、单笔上限各一正一反。
- 只能购买一次：第二单被拒；取消后可再买。
- 每日限购：当天超限被拒；第二天重新计；昨天的单今天取消退回昨天的周期。
- 共享键：两个商品合计不超过限额。
- 门店范围：两家门店分别计。
- 手机号维度：同一手机号的另一个账号被拒；未绑定手机号被拒。
- 新客专享：首单待支付时第二单被拒；买过东西的会员被拒；全额退款后按口径判断。
- 退款退回：规则允许时可再买，不允许时仍被拒。
- 并发：限购 3 件 12 线程只成 3 单；只能买一次与新客专享 10 线程只成 1 单。
- 超出部分按原价：3 件限 2 件时拆成 2 件活动价与 1 件原价，只计 2 件名额；名额用完后整行原价且不报限购问题；只能买一次或新客专享用过后按原价；起售与单笔上限按全部件数；原价缺失或不高于活动价时报规则错误；取消后活动价名额回来。
- 迁移：旧计数表的数据迁入新表，可回退。
