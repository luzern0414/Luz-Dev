# 余额、储值与积分账户

参考代码：`backend/15-recharge/code/wallet/__init__.py`（储值钱包），测试 5 项（含并发不为负）；积分见 `backend/14-membership/`。
相关规范：MONEY-004、MBR-001、MBR-002、RFD-004。

## 1. 账户 + 流水（复式思路）

| 表 | 内容 | 约束 |
|---|---|---|
| 账户 `wallet_accounts` | 当前余额：本金、赠送金（积分账户：可用、冻结） | 每用户一行；余额由条件更新维护，不为负 |
| 流水 `wallet_ledger` | 每次变化：类型、本金变化、赠送变化、业务单号、时间 | 只追加；唯一约束 `ref + kind` 防重复记账 |

规则：余额只能通过账户服务变化；每次变化同时写流水；流水累加 = 账户余额（每日对账）。

## 2. 本金与赠送金分开

“充 1000 送 200”时，本金 1000、赠送 200 分别记账：

| 场景 | 处理 |
|---|---|
| 消费 | 按策略拆分：`proportional`（按余额比例，默认）或 `principal_first`；拆分结果写入流水 |
| 订单退款 | 按原消费流水的拆分原路退回钱包（`reverse`） |
| 退卡 | 只退剩余本金，赠送金作废，账户关闭（`refund_card`）；冷静期内未消费按合同全额退本金 |
| 开票 / 统计 | 只按本金计收入 |

健身、美业等预付消费要按当地预付卡规定与合同示范文本处理冷静期、转让、退费时限（MBR-002，例：北京体育健身预付费合同示范文本 7 日冷静期、5 日内退回、原路退回）。

## 3. 并发与幂等

- 扣减：`UPDATE … SET principal = principal - p, bonus = bonus - b WHERE id = ? AND principal >= p AND bonus >= b`。
- 充值以支付单号为 `ref`，消费以订单号为 `ref`，重复请求返回原流水。
- 冻结：需要“先冻结后扣”（如押金、预授权）时增加冻结字段，冻结 → 扣减 / 解冻都是条件更新。

## 4. 积分

| 规则 | 做法 |
|---|---|
| 发放 | 支付成功事件触发，按订单号幂等；退款回扣 |
| 过期 | 按批次（获得时间）先进先出过期，过期任务写流水 |
| 回扣不足 | 方案写明：允许为负、从后续积分扣、或放弃回扣（不可默认静默为 0） |
| 抵扣 | 作为支付方式记录，退款时退回积分 |

## 5. 测试清单

- 重复充值、重复消费、重复冲回只记一次。
- 并发消费不出现负余额，成功次数与余额一致。
- 拆分合计等于消费金额，本金与赠送都不为负（随机测试）。
- 退卡只退本金且账户关闭后不可再用。
- 流水累加等于余额。
