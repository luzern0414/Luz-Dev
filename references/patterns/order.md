# 订单：下单流程、状态机与超时关单

参考代码：`backend/08-order/code/order/__init__.py`（创建、流转、取消）、`order/jobs.py`（超时关单），测试 12 项。
相关：inventory.md（预占）、pricing.md（计价）、consistency.md（幂等与发件箱）、`backend/09-wechat-pay/MODULE.md`（支付）。
相关规范：ORDER-001～ORDER-006、MONEY-001～MONEY-003、PAY-001、PAY-010、UI-002。

## 1. 下单流程

| 步骤 | 接口 | 做什么 | 关键约束 |
|---|---|---|---|
| 1 试算 | `POST /orders/preview` | 读取商品、库存、可用优惠，返回应付金额与 `quote_token`（有效期如 10 分钟） | 不扣库存、不锁券；价格以服务端为准 |
| 2 提交 | `POST /orders`（`Idempotency-Key`） | 校验 `quote_token` 与当前价格一致 → 同一事务：预占库存、锁定券、写订单与明细（价格与优惠快照、分摊结果）、写发件箱 | 价格变化返回 `QUOTE_EXPIRED` 让用户重新确认；任一失败整体回滚 |
| 3 支付 | `POST /orders/{id}/pay` | 创建或复用支付单（见支付模块） | 只对待支付订单 |
| 4 支付成功 | 回调 / 查单 | 订单 → 已支付；预占确认、券核销；发件箱触发履约 | 条件更新，幂等 |
| 5 履约 | 发货 / 核销 / 开课 | 订单 → 履约中 / 已完成 | 小程序录入发货信息（MP-005） |
| 6 售后 | 见 after-sales.md | 部分或全部退款 | 金额按分摊结果 |

**价格快照**：订单明细保存下单时的商品名、规格、单价、数量、分摊优惠、实付。历史订单、退款、对账都只用快照，不再读商品表（ORDER-005）。

## 2. 状态机

| 状态 | 含义 | 可到达 |
|---|---|---|
| `pending_payment` | 待支付（库存已预占） | `paid`、`cancelled` |
| `paid` | 已支付 | `fulfilling`（或 `shipped`）、`refunded`（全额退款） |
| `fulfilling` / `shipped` | 履约中 / 已发货 | `completed` |
| `completed` | 已完成 | 终态（售后另建售后单，不改订单主状态，或改为 `partially_refunded`） |
| `cancelled` | 已取消 | 终态 |
| `refunded` | 已全额退款 | 终态 |

所有流转用 `luzback.StateMachine.advance`：`UPDATE … WHERE id = ? AND status = 旧状态`，影响 0 行即冲突，返回稳定错误，不覆盖新状态（ORDER-001）。每次流转写订单操作日志（谁、何时、从哪到哪、原因）。

## 3. 超时关单

| 方案 | 做法 | 优点 | 缺点 | 何时用 |
|---|---|---|---|---|
| **定时扫描（默认）** | 每分钟扫描 `pending_payment` 且 `created_at` 早于时限的订单 | 简单、可靠、天然可重试 | 有分钟级延迟；订单量大时扫描成本高 | 绝大多数门店与中小电商 |
| Redis 有序集合 | 以到期时间为分数，轮询取出到期订单 | 延迟低 | Redis 丢数据时漏单，必须保留扫描兜底 | 订单量大 |
| 消息队列延迟消息 | 下单时投递延迟消息 | 延迟低、解耦 | 依赖 MQ；消息丢失仍需兜底 | 已有 MQ |

无论哪种触发方式，都调用同一个关单函数，并保留定时扫描兜底。关单函数的顺序（与微信支付开发指引一致）：

```text
查询支付 → 已支付：按支付成功处理（不能取消）
         → 查询失败 / 未知：本轮跳过，下轮再查
         → 未支付：关闭渠道订单 → 取消本地订单 → 释放库存与券
```

关单接口失败时不取消本地订单，下轮重试；每个订单独立提交，互不影响（`order/jobs.py`，测试 `test_order_jobs.py`）。

## 4. 订单号

| 要求 | 做法 |
|---|---|
| 唯一、不可枚举 | 时间前缀 + 随机或号段；不要用自增 ID 对外 |
| 满足支付约束 | 微信 out_trade_no 6–32 位，只含数字、字母、`_-|*`（PAY-002） |
| 可排查 | 包含日期，便于按日对账 |

## 5. 取消与修改

- 用户只能取消待支付订单；已支付取消走售后 / 退款。
- 已提交的订单不改金额；需要改价时由后台改价单（写审计），在支付前生效，并重新下单渠道支付单。
- 地址、备注等不影响金额的字段，在履约前可改，写操作日志。

## 6. 测试清单

- 同一幂等键重复提交只生成一个订单；不同请求体复用幂等键报错。
- 价格变化后提交返回 `QUOTE_EXPIRED`。
- 任一 SKU 不足时不生成订单、不占用任何库存。
- 非法流转与并发流转返回冲突，不覆盖。
- 超时关单：已付不取消；查询失败或关单失败不取消；重复执行不重复回补。
- 历史订单金额不随商品改价变化；只能查询本人订单。
