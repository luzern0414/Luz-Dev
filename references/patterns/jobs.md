# 定时任务与延迟任务

参考代码：`backend/00-framework/code/luzback/scheduler.py`、`backend/08-order/code/order/jobs.py`（超时关单）、`booking.mark_no_shows`、`inventory.reservation.expired_refs`。
相关规范：ORDER-004、PAY-010、RFD-003、RFD-005、OBS-003。

## 1. 常见任务

| 任务 | 频率 | 要点 |
|---|---|---|
| 超时关单 | 每分钟 | 先查单再关单（order.md §3） |
| 支付确认中查单 | 每分钟 | 待支付超过 2 分钟的支付单主动查单（PAY-010） |
| 退款查询 | 每分钟，5 分钟后衰减 | 处理中退款（RFD-003） |
| 预占过期释放 | 每分钟 | 与关单共用或独立 |
| 对账 | 每日 10 点后 | 下载前一天账单（RFD-005） |
| 券 / 积分过期 | 每日 | 写流水 |
| 爽约标记、排课生成 | 每日 / 每小时 | 幂等 |
| 发件箱投递、死信告警 | 持续 | consistency.md |

## 2. 设计规则

| 规则 | 做法 |
|---|---|
| 可重复执行 | 任务逻辑全部基于状态机条件更新与唯一约束，重复执行不重复生效 |
| 单实例执行 | 多实例部署时用数据库行锁（`SELECT … FOR UPDATE SKIP LOCKED` 取任务）或租约锁（锁有过期时间并续期）；锁只防重复工作，正确性仍靠幂等 |
| 分批 | 每轮限量（如 100 条），按时间排序；处理不完下轮继续 |
| 单条隔离 | 每条记录独立提交；一条失败不影响其他 |
| 外部失败 | 查单 / 关单失败保持原状态，下轮重试，不推断结果 |
| 可观测 | 记录每轮处理数、失败数、耗时；积压超过阈值告警 |
| 时间 | 用注入的 `now` 便于测试；按 UTC 存储，业务日按门店时区 |

## 3. 延迟任务方案

| 方案 | 适用 | 注意 |
|---|---|---|
| 定时扫描（默认） | 绝大多数 | 分钟级延迟可接受；为扫描条件建索引（状态 + 时间） |
| Redis 有序集合 / 延迟队列 | 量大、要求秒级 | 必须保留扫描兜底 |
| MQ 延迟消息 | 已有 MQ | 消息丢失仍需兜底 |

## 4. 测试清单

- 重复执行结果不变；并发两个实例执行不重复处理。
- 外部接口失败时记录保持原状态。
- 批量上限生效；单条失败不阻塞后续。
