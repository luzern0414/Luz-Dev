# 预约名额与排期（课程、教练、场地、服务）

参考代码：`backend/13-reservation/code/booking/__init__.py`，测试 7 项（含 40 并发抢 8 个名额）。
相关：inventory.md（名额即库存）、accounts.md（次卡扣次）、notification（递补通知）。
相关规范：ORDER-001、ORDER-003、FACE-001（刷脸签到须有替代方式）。

## 1. 模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| 时段 `booking_slots` | 资源（课程 / 教练 / 场地）、开始、结束、容量、已约、状态 | 由排课生成；容量 = 名额 |
| 预约 `bookings` | 时段、用户、状态、排队时间 | 唯一约束（时段, 用户）：一人一约；取消后再约复用记录 |

状态：`booked → checked_in | cancelled | no_show`；`waitlisted → booked | cancelled`；`cancelled → booked | waitlisted`（重新预约）；`checked_in`、`no_show` 为终态。

## 2. 规则

| 规则 | 做法 |
|---|---|
| 不超约 | `UPDATE slots SET booked = booked + 1 WHERE id = ? AND booked < capacity AND status = 'open'` |
| 一人一约 | 唯一约束；重复提交返回已有预约 |
| 时间冲突 | 同一用户已约时段与新时段重叠时拒绝；教练排课同理 |
| 候补 | 满员可排队；有人取消时同一事务内递补队首并写发件箱通知 |
| 取消截止 | 开课前 N 分钟内不可自助取消；迟取消 / 爽约规则（扣次、限制预约）由商户确认 |
| 签到 | 开课前 N 分钟至下课可签到；刷脸签到须提供扫码或人工签到替代 |
| 爽约 | 下课后仍为 `booked` 的由任务标记为 `no_show` |
| 次卡 / 课时 | 预约时冻结一次，签到确认扣减，取消解冻（与 accounts.md 的冻结同理） |
| 课程取消 | 商户取消时段时批量取消预约、解冻次数、通知用户 |

## 3. 排课

- 周期排课生成具体时段（例如每周二 19:00），生成任务幂等（资源 + 开始时间唯一）。
- 修改已有预约的时段（改时间、减容量）需要通知已预约用户；容量不能小于已约人数，否则先处理多余预约。
- 时区：营业时间按门店时区存储与计算（DATA-004）。

## 4. 测试清单

- 并发预约不超过容量；重复提交只占一个名额。
- 时间冲突拒绝；候补递补按排队顺序；取消释放名额。
- 截止时间内用户取消被拒、门店人员可取消。
- 签到窗口外拒绝；爽约任务可重复执行。
