# 门禁入场、在场管理与设备接入（无人值守场馆）

适用：无人健身房、自助场馆、自助自习室、共享空间。相关规范：ACC-001～ACC-003、IOT-001～IOT-003、FACE-001～FACE-006。

## 1. 入场判定

```text
小程序请求动态入场码（30–60 秒刷新，签名，一次有效）
 → 门禁扫码 / 人脸识别 → 设备把凭证提交服务端
 → 服务端在一个事务内：校验凭证 → 校验资格（卡有效期、门店、时段、次数余额、禁用、欠费）
   → 门店在场人数 < 容量（条件更新）→ 本人无未关闭在场记录（唯一约束）→ 次卡扣次（按入场请求幂等）
   → 写入场记录与开门指令
 → 签名指令下发设备（指令 ID 唯一、10 秒过期）→ 设备执行并回执
```

拒绝时返回明确原因（卡已过期、不在可用时段、场馆已满、你已在场内、次数不足），用于小程序与设备屏显示。

## 2. 在场与离场

| 状态 | 进入条件 | 处理 |
|---|---|---|
| 在场 | 入场开门成功 | 计入门店在场人数；计时开始（按时长计费时） |
| 已离场 | 离场刷码 / 出门感应 | 在场人数减一；按时长计费时结算 |
| 超时提醒 | 在场超过设定时长 | 小程序提醒，值班告警 |
| 异常离场 | 营业规则时间后仍未离场 | 任务关闭在场记录并标记，计费按规则，可申诉 |

在场记录对“会员 + 未关闭”建唯一约束，防止一人多次进入或借卡带人。

## 3. 设备接入

| 能力 | 做法 |
|---|---|
| 连接 | 设备通过 MQTT over TLS 连接消息服务器；每台设备独立凭证，按设备 ID 限制可订阅与发布的主题 |
| 指令 | 指令表记录：指令 ID、设备、类型（开门、开灯、开柜）、参数、签名、过期时间、状态（排队 → 已发送 → 已回执 / 失败 / 过期） |
| 心跳 | 设备定时上报；超时标记离线并告警 |
| 离线降级 | 预先下发有效会员的离线凭证（带过期时间）；离线进出事件本地保存，恢复后去重补传 |
| 厂商适配 | 不同品牌门禁、闸机、电控通过适配器接入，业务层只认统一指令 |
| 联动 | 在场人数为 0 时关闭灯光空调；首人入场时开启 |

## 4. 无人值守安全

- 场内求助（小程序与现场按钮）直达值班人员，记录响应时间。
- 告警：长时间在场、夜间异常、设备离线、门长时间未关、求助。
- 消防与逃生由硬件保证：火警或断电时门可从内部打开，不依赖系统指令。
- 监控画面保存期限、调取权限与审计写入方案；人脸采集遵守人脸规则（单独同意、可替代、设备本地存储、私密空间禁止安装）。

## 5. 测试清单

- 并发入场不超过容量；同一账号未离场不能再次入场；重复入场请求只扣一次。
- 过期、重复、他人的入场码被拒绝；伪造、重放、过期的开门指令不执行。
- 断网后会员凭有效离线凭证进出，恢复后记录完整无重复。
- 超时提醒、异常离场关闭、按时长计费结算正确。
